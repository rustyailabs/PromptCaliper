Security

Auth Flow

JWT-based login with silent refresh and server-side invalidation

① First Load

App calls GET /api/auth/me. If 401 → show LoginView. If 200 → render main app.

② Login

POST /api/auth/login returns access_token (15 min) + refresh_token (7 days). Both stored in localStorage.

③ Silent Refresh

Axios interceptor catches any 401. Auto-calls POST /api/auth/refresh with refresh token. On success, retries original request. On failure, dispatches ft:logout event.

④ Logout

POST /api/auth/logout stores the refresh token's JTI in a server-side blocklist. Clears localStorage. Blocklisted tokens are rejected on any future refresh attempt.

Capabilities

Platform Features

All managed from the admin console — no config files to edit manually

🔑

Virtual Keys

Scoped API keys for users and services. Full key shown once at creation.

  • SHA-256 hash stored — raw key never persisted
  • Per-key monthly budget + RPM/TPM limits
  • One-click rotation — new key, same settings
  • Assign to teams for group budgeting
🗺️

LiteLLM Routing

Intelligent request routing across all major LLM providers.

  • Load balancing — least-busy or latency-based
  • Automatic fallbacks on provider errors
  • Configurable routing weights per model
  • Hot-reload — no restart needed after config change
💰

Budget Control

Monthly spend limits enforced in real time, at multiple scopes.

  • Global org / per-team / per-key / per-model limits
  • Actions: block (429) · alert only · block + alert
  • Append-only spend ledger for full auditability
  • Auto-reset on 1st of month via APScheduler
🚦

Rate Limiting

RPM and TPM enforcement per virtual key or team.

  • Sliding window algorithm
  • In-memory counters for dev (single process)
  • Redis counters for prod (multi-process safe)
  • Live current-usage visible in admin console
🛡️

Guardrails

Content filtering applied before and/or after every LLM call.

  • Keyword block — exact word list
  • Regex filter — arbitrary pattern
  • PII redaction — email, SSN, phone, card numbers
  • Content filter — violence/adult category flags
⚡

Response Caching

LiteLLM-managed cache cuts latency and provider costs.

  • Local (in-memory) for dev
  • Redis exact-match for prod
  • Redis semantic cache — embedding similarity
  • Configurable TTL and similarity threshold
📊

Observability

Full audit log of every request — prompt, response, tokens, cost, latency.

  • Paginated log viewer with inline expansion
  • Filters: status, model, cache hit, search
  • Analytics: 6-month team spend, 7-day token trend
  • Model cost distribution pie chart
🔔

Alerts

Threshold-based notifications on any metric.

  • Metrics: spend $, spend %, RPM, error rate, p95 latency
  • Scope: global / team / key / model
  • Channels: log · email · webhook · Slack
  • Evaluated every 5 minutes by APScheduler

Evolution

Recent Changes & Architecture Impact

What changed, why it changed, and how it affects the system design

2025-03 · commit 2c522a5 Analytics

AnalyticsView — Enhanced Token Economics & Spend Visibility

The Analytics view was overhauled to surface deeper token-level economics and make team spend attribution more actionable.

  • 7-day token economics chart now explicitly separates input tokens vs output tokens — critical because output tokens are 3–5× more expensive per token across all providers
  • 6-month org spend bar chart now groups by team, enabling finance chargeback without external BI tools
  • Model cost distribution pie chart added — shows which models consume the highest dollar share so teams can make cost/quality tradeoff decisions
  • Architecture impact: The /api/analytics router now aggregates directly from the spend_ledger table (the append-only source of truth) rather than from mutable key counters — ensuring consistency between what the ledger records and what analytics shows. The request_logs table is used for latency and token trend data
2025-03 · commit 9c7d243 Workflow

Updated Request Workflow — Guardrail Trigger Visibility

The 8-step request pipeline was tightened to ensure guardrail trigger events are visible across the full audit trail, not just in the guardrail log.

  • guardrail_triggered flag is now written to request_logs for every call — a triggered-but-passed (flag action) entry is distinguishable from a clean pass
  • Blocked requests (guardrail action = block) now log a 400-status entry before returning — ensuring rejected requests appear in the audit log and analytics error-rate counters
  • PII redaction events in both input and output phases are captured in the log metadata — supporting compliance evidence that PII was actively removed
  • Architecture impact: Step 5 (Input Guards) and Step 7 (Output Guards) now always write to request_logs regardless of the guardrail action. Step 8 (Log & Ledger) now reads the guardrail state accumulated in the request context object and persists it atomically with the rest of the log entry
2025-03 · commit 7adee31 UI / Design

Design System Refresh — Rusty AI Labs Visual Language

The admin console's visual language was updated across all views for consistency and readability.

  • CSS custom property system (RustyStyles.jsx) standardised — all colour tokens, spacing, and typography now flow from a single source
  • Dark/light theme toggle updated to respect OS preference on first load via prefers-color-scheme media query
  • Card hover states, border accents, and badge chips made consistent across Virtual Keys, Models, Guardrails, and Alerts views
  • Architecture impact: No backend changes. The ThemeContext in the frontend now controls a single data-theme attribute on <html> — CSS variables cascade from there, eliminating the need for per-component theme conditionals
2025-03 · commit 23e54b8 Brand

Brand Website Link — Navigation & Identity

Added brand website link to the admin console navigation for product identity and support access.

  • Navigation bar updated to include the Rusty AI Labs brand link
  • Logo / favicon wired to public/promptcaliper.svg for consistent browser tab identity
  • Architecture impact: Static asset only — no backend change. The SVG is served directly by Vite in dev and by the nginx frontend container in production
Planned / Roadmap Upcoming

Architecture Considerations for Future Milestones

Items under active consideration that would touch the core architecture:

  • Streaming support end-to-end: LiteLLM supports SSE streaming; the FastAPI layer would need to proxy StreamingResponse and defer log/ledger write to a background task to avoid blocking the stream
  • Multi-tenant namespacing: Adding a tenant_id FK across all major tables would allow the gateway to serve multiple isolated orgs from a single deployment — a read-path filter change rather than a schema change
  • Webhook outbound callbacks: Alert channel currently sends fire-and-forget HTTP POST; moving this to an async task queue (Celery or asyncio background tasks) would decouple alert latency from the 5-min APScheduler cycle
  • RBAC on virtual keys: Extend the virtual_keys table with a role column to support read-only vs write-capable keys for different integration patterns
